Kernel and persistence controls
-------------------------------
Only Service actors produce observations through a separate internal RecordTimingFact request in the existing ops::apply kernel. Its OWN receipt, admitted revision, journal ordinal and timing record commit together. The referenced original committed request, original event sequence/time/revision remain separate. There is no canonical after-journal timing hook: HandoutIntent/Outcome and native/lifecycle admission never depend on optional observation storage. Reads, denied/stale/storage-failed and receipt-replayed operations do not create companions. Storage errors roll back; they are not converted into source absence or replay under another UUID. This optional display companion never becomes a prerequisite for native/lifecycle admission.

Own RecordTimingFact requests are excluded from the service-operation source observer. A task snapshot is sampled only by the existing service observation path, under its original project lock. Meaningful state/attempt/binding/source/epoch changes record immediately. An unchanged source is coalesced before allocating a request; at most one immutable watermark per unit per 60 seconds. A same-source duplicate/out-of-order candidate accepted as a no-op does not advance the team revision or append a journal/fact; its saved common-kernel receipt only settles an already-created racing request. Source team-revision changes, timing reads, browser visibility and the timing writer's own journal entries do not make a source change. Initial old snapshots remain points/gaps, never continuous historical intervals.

Every fact and historical snapshot is immutable. A small mutable writer head may be used only for deduplication; reads never join that head into a frozen page. The cursor freezes its selected finite unit cohort independently of whole-phase live.complete. The immutable registry has one entry per FULL ObservedUnitKey, including attempt, binding, generation and publication, not per node ID. The cohort contains at most 200 registry IDs plus complete keys; a node filter never merges keys. An opaque cursor freezes these IDs as 16-character hexadecimal tokens and resolves them by indexed immutable point reads. All registry metadata and returned rows count against the inclusive 1 MiB response budget. A registry/selection and each indexed unit stream have explicit limits; byte lookahead measures before loading payloads. An over-cohort page is explicitly partial. The default window ends at the last verified observation of that selected cohort, not an unrelated later unit. More/off-page/truncated/unsupported coverage cannot become a phase aggregate or an implementation actual.

Source/runtime qualification is pending. This document pins the interface; it does not claim that code, old-engine compatibility, native coverage or UI runtime has passed.

Original-source and recovery boundary
------------------------------------
The existing service pass selects at most 200 latest LIVE journal metadata entries using the shipped journal_page(team,seq) index. It only considers typed handout/reopen intent/outcome events; it never observes its own timing operation. A selected source is rechecked by its original request primary key and exact (team,seq) point lookup in journal or journal_archive, with bounded body/result lengths and LIMIT 2. No new index is built over requests, journal, journal_archive or effects. Old sources outside this finite window remain unavailable; this is not historical completeness. A selected source can survive the ordinary live-to-archive move because its original sequence is retained.

Only the optional writer initializes empty observation companion tables/indexes. Reads and canonical actions do not initialize or migrate them. This still shares the SQLite writer lock: qualification measures optional initialization with a retained archive and a competing canonical action, rather than assuming a separate transaction bounds lock time.

The service retains an exact pending timing payload/UUID in its existing actor ledger before applying it. Recovery checks the exact receipt first; a committed receipt returns without re-execution. Partial/unreadable evidence stays unknown. Only a definitely uncommitted settled result may re-enter the ordinary kernel with the same payload/UUID. No blind repost or replacement UUID is permitted.

The observed cursor has its own 8192-byte end-to-end bound. Existing unrelated cursor routes retain 2048 bytes. Next/First use the same selected lease/poller; retiring a read generation does not change the cleanup lease. Tests qualify a genuine 200-ID token above 2048, the 8192/8193 boundary and exact membership under append/archive, including over 200 full keys on one node.

Selected-window sequence sampling is bounded before filtering: each of at most 200 exact unit streams reads only limit+1 sequence metadata rows at or below the frozen ceiling, via observed_timing_unit_page. The merge inspects at most 200 newest metadata entries (plus lookahead) and loads only fitting in-window payloads. Next moves backwards by the immutable sequence, never by browser time. Any excluded window sample is explicitly partial: a clock reversal cannot force an all-history scan or imply complete window coverage. Last-verified gap anchors retain their own observed-at time and never extend duration.

The page scope binds the actual returned selected publication identity/generation in any state (including a reservation while the outer phase label is Draft). This is a read-scope identity, not evidence of approval, settled publication or a fact's original membership. Historical fact.key.publication remains independently nullable; current page/phase labels never fill it.

Schema 1 overlap rule: gap, source-unavailable, restart or clock-discontinuity takes precedence over sampled-point coverage for that returned unit. Otherwise on-page verified points are Sampled, never continuous. Task-state and service-bookkeeping points may coexist without either becoming implementation. The supported duration interval set is empty in this schema; its overlap union and every implementation actual remain unavailable/None, not zero. Existing slice 2 recorded delivery bookkeeping is separate. Later native duration categories require new qualified provenance/coverage before any numerical union is exposed.
