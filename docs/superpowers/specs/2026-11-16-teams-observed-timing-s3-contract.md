Kernel and persistence controls
-------------------------------
Only service actors produce observations through the existing ops::apply transaction. The operation receipt, admitted revision, original journal source and immutable timing record commit together. Reads, denied/stale/storage-failed and receipt-replayed operations do not create companions. Storage errors roll back; they are not converted into source absence or replay under another UUID. This optional display companion never becomes a prerequisite for native/lifecycle admission.

Own RecordTimingFact requests are excluded from the service-operation source observer. A task snapshot is sampled only by the existing service observation path, under its original project lock. Meaningful state/attempt/binding/source/epoch changes record immediately. An unchanged source is coalesced before allocating a request; at most one immutable watermark per unit per 60 seconds. A same-source duplicate/out-of-order candidate accepted as a no-op does not advance the team revision or append a journal/fact; its saved common-kernel receipt only settles an already-created racing request. Source team-revision changes, timing reads, browser visibility and the timing writer's own journal entries do not make a source change. Initial old snapshots remain points/gaps, never continuous historical intervals.

Every fact and historical snapshot is immutable. A small mutable writer head may be used only for deduplication; reads never join that head into a frozen page. The cursor freezes its selected finite unit cohort independently of whole-phase live.complete. A registry/selection and each indexed unit stream have explicit limits; byte lookahead measures before loading payloads. An over-cohort page is explicitly partial. The default window ends at the last verified observation of that selected cohort, not an unrelated later unit. More/off-page/truncated/unsupported coverage cannot become a phase aggregate or an implementation actual.
